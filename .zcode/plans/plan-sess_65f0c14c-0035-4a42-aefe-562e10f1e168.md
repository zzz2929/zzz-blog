## 全站自适应等比缩放方案（zoom 路线）

**目标**：以 1920px 宽为设计基准（当前样子完全不变），整个站点随视口宽度等比缩放——2K/4K 屏内容等比变大、笔记本等比变小、任何 Windows 缩放率下版面比例一致；<768px 移动端保持现有自适应布局不缩放。

**为什么不走 px→rem 全量重构**：调研确认全站 25 个文件约 700+ 处硬编码布局 px（组件内联 style 为主），且存在 7 组几何强耦合数值族（如随笔时间轴 1032=4×240+3×24 全族）。逐个换算 rem 工作量巨大、回归风险高。而 CSS 标准属性 `zoom` 对所有 px（含内联样式、星空动画、时间轴几何）统一等比作用，一行核心规则即可达成"所有元素自适应比例"，浏览器按实际像素栅格化，缩放后文字依然清晰。

### 改动清单（共 2 个文件）

**1. `src/styles/global.css`** — 核心规则：
```css
html {
  font-size: 14px;
  zoom: clamp(0.5, calc(100vw / 1920px), 1.25);
}
@media (max-width: 767px) {
  html { zoom: 1; }  /* 移动端保持现有布局 */
}
```
- 1920 屏 → zoom 1（和现在完全一样）；2560 → 1.33；1366 → 0.71；上限 1.25 / 下限 0.5 保护极端情况
- 不支持 calc 长度除法的旧浏览器会忽略该声明、回退到 zoom:1（即现状），优雅降级
- zoom 会把全站所有 px（Header、音乐页、MiniPlayer、内联样式、时间轴、星空）自动等比缩放

**2. `src/pages/essay.astro`** — 三处联动修正：
- 删除 `@media (max-width: 1069px)` 的时间轴换行退化：zoom 下 1032px 行永远等比放得下（1032×0.5=516 < 最窄可用宽度），原断点反而会在笔记本上错误触发竖排堆叠
- 换行退化断点改为 `@media (max-width: 767px)`（与移动端 zoom=1 区间对齐，覆盖手机竖屏）
- `fitCardWidths()` JS：zoom 下 `getBoundingClientRect` 返回的是视觉像素，而 `style.width` 是布局像素，需除以 zoom 再加 34px 内边距常数，否则单图卡片宽度适配在非 1920 屏会失准

### 明确不动的
- Header/音乐页/MiniPlayer/HeroModule 等全部内联 px（zoom 自动等比）
- 星空 box-shadow 坐标（装饰画布）
- MiniPlayer 定位公式（其中 100% 与 1350px 项同处布局像素空间，缩放下自洽）
- 移动端已有断点（汉堡菜单、hero 高度、TOC 隐藏等）

### 验证步骤
1. `pnpm build` 通过
2. 浏览器在 1920/1440/1366/900/768 五档视口宽度下截图对比：比例一致性、Header 与页脚对齐、随笔时间轴节点对齐、下拉面板、灯箱
3. 非 1920 视口下检查随笔单图卡片宽度贴合（fitCardWidths 修正后）
4. 确认 1920 下与改动前视觉零差异

### 风险与回退
- `zoom` 已是标准化属性（2024 起全主流浏览器一致），但仍在 <768 移动端和极端视口做了回退；如个别页面在特定缩放档位出现错位，可对单独元素设置 `zoom: 1` 精确豁免
- 上下限（0.5/1.25）与基准（1920）是可调常数，集中在一处
